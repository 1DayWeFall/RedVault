# 薯藏 RedVault

> 将小红书收藏转化为可检索、可复用、真正属于自己的本地知识库。

RedVault 是一个本地优先的个人知识管理工具：在浏览器登录态内采集小红书收藏，先将原始数据放入收件箱，用户确认后再进行 AI 整理，并把结果写入 Obsidian 兼容的 Markdown Vault。它同时提供列表、搜索、状态看板和交互式知识画布，让用户可以从一条收藏一路追踪到结构化笔记和原始内容。

## 为什么做它

收藏并不等于拥有。小红书收藏通常面临三个问题：内容分散在平台内部，平台链接和推荐流不稳定；收藏数量增长后很难按主题找回；AI 整理如果直接覆盖原文，用户无法判断哪些是原帖事实、哪些是模型推断。

RedVault 的设计目标不是“再做一个收藏夹”，而是建立一条可检查的内容资产链：

```text
浏览器登录态采集
        ↓
原始 JSON 收件箱
        ↓ 用户确认
AI 整理 / 无 AI 降级
        ↓
Markdown Vault + 索引
        ↓
列表搜索 · 状态看板 · 交互画布 · 详情阅读
```

## 当前能力

### 已实现的主路径

- 在浏览器登录状态下采集收藏详情、图片、视频字幕和评论
- 原始内容先进入收件箱，支持预览、确认、失败重试和处理状态查看
- AI 可以帮助提炼摘要、分类和标签；没有 AI 时仍然保存原文
- 生成可被 Obsidian 等工具继续使用的本地笔记，并保留原始内容
- 笔记库支持分类树、标签、关键词搜索、详情抽屉和备注编辑
- 看板展示领域 → 分类 → 子分类 → 笔记的结构关系
- 交互画布支持拖拽、平移、缩放、关键词/分类过滤和节点详情跳转

## 产品界面

当前入口按用户任务组织为：

```text
收件箱 → 知识库 → 看板 → 画布 → 设置
```

| 视图 | 解决的问题 |
| --- | --- |
| 收件箱 | 哪些收藏刚采集、哪些等待确认、哪些失败了？ |
| 知识库 | 已入库的笔记有哪些，如何搜索和筛选？ |
| 看板 | 收藏内容按哪些领域和分类组织？ |
| 画布 | 知识节点之间的层级关系如何直观浏览？ |
| 详情 | 原帖内容、AI 整理、来源状态和个人备注是什么？ |

画布把分类层级和笔记节点放在同一张知识地图中，适合从整体结构浏览收藏，再进入单篇笔记阅读。

## 快速开始

### 你需要准备什么

| 内容 | 是否必需 | 用途 |
| --- | --- | --- |
| RedVault 仓库 | 必需 | 服务和前端都在这里，直接从 GitHub 下载 ZIP 或 clone |
| Node.js 18+ | 必需 | 启动本地服务；Windows 启动脚本会自动寻找已安装的 Node |
| Chrome/Edge + Tampermonkey | 采集时必需 | 在浏览器登录状态下读取收藏内容 |
| Obsidian | 可选 | 打开生成的本地 Markdown 笔记 |
| AI 服务配置 | 可选 | 生成摘要、分类和标签；没有 AI 也能保存原文 |

不需要单独下载 `data/`、`vault/` 或 `node_modules/`：这些是运行时数据或安装后生成的内容。不要把自己的 `data/` 和 Vault 上传到 GitHub。

### 第一次安装

1. 在 GitHub 点击 **Code → Download ZIP**，解压到一个不会经常移动的目录；或者使用 `git clone`。
2. 安装 Node.js 18+。如果使用 Windows，之后可以直接双击仓库根目录的 `start.cmd`。
3. 第一次启动前，在仓库目录运行：

   ```powershell
   npm install
   ```

4. 双击 `start.cmd`。服务启动后会自动打开 `http://127.0.0.1:3789/`；命令行用户也可以运行 `npm start` 后手动打开这个地址。
5. 打开页面右上角的「设置」：
   - 选择笔记保存位置。可以使用默认的项目内目录，也可以填写一个已有的 Obsidian Vault 路径；
   - 如果要使用 AI，填写文本模型的地址、模型名和 API Key，并点击「测试连接」；
   - 在「脚本安装」中下载或复制采集脚本。
6. 在 Tampermonkey 中新建用户脚本，把 `userscript/xhs_capture.user.js` 的内容粘贴进去并保存。
7. 回到 RedVault「设置」中显示并复制「上报令牌」，填入脚本顶部的 `CONFIG.TOKEN`，再保存脚本。

完成后，浏览器采集到的内容才会进入本机的收件箱。令牌只用于本机脚本向本机服务上报；如果在设置中重置令牌，需要同步更新脚本里的值。

### 日常使用

每次使用 RedVault 时：

1. 双击 `start.cmd`，等待页面自动打开；
2. 确认浏览器已登录小红书，打开收藏夹或浏览想保存的笔记；
3. 采集内容会出现在 RedVault 的「收件箱」；
4. 在收件箱检查标题、正文和图片，选择想整理的内容并点击「确认」；
5. 等待处理完成。失败项会保留在收件箱，可查看原因并点击「重试」；
6. 在「知识库」中搜索和阅读，在「看板」和「画布」中浏览整体分类；
7. 需要结束服务时运行 `stop.cmd`。

首次使用建议先采集 1～2 篇笔记，确认收件箱、AI 设置和 Vault 路径都正常，再批量采集。

### 数据保存在哪里

- `data/`：本地配置、采集令牌、收件箱和索引，不提交到 GitHub；
- Vault 目录：生成的 Markdown 笔记和附件，路径在「设置」中配置；
- 浏览器：只保存画布视口等界面偏好。

备份或换电脑时，至少同时保留 Vault 和 `data/`；其中 `data/` 含有配置和本机采集状态，不要公开分享。

## 数据与文件结构

```text
server/                 Express API、业务服务和 AI 管线
public/                 原生前端，无构建链
userscript/             浏览器采集脚本
tests/                  node:test 自动测试
docs/DESIGN.md          架构唯一事实源
data/                   本地运行时数据（gitignored）
start.cmd               Windows 隐藏式启动入口
stop.cmd                Windows 停止入口
```

用户 Vault 路径由 `data/config.json` 的 `vaultPath` 配置，笔记以普通 Markdown 文件保存。

## 项目亮点

项目的核心价值在于把内容采集、整理、存储和复用连接成一个可操作的闭环：

- 从收藏痛点抽象出收件箱、状态和确认机制
- 保留原帖内容，将 AI 整理作为可追踪的补充信息
- 对 AI 失败和未整理内容提供明确的恢复与识别路径
- 用看板和画布降低知识结构的理解成本
- 通过自动测试和浏览器回归保证主流程可复现

## 项目边界

RedVault 是个人本地知识管理工具，不是小红书官方客户端，也不提供绕过登录、风控或平台访问限制的能力。使用者应遵守目标平台的服务条款、隐私要求和适用法律。
