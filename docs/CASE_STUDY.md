# RedVault 项目案例记录

> 这份文档用于沉淀真实使用证据。没有实际测量的数据保持空白，不用估算值或宣传性数字替代。

## 一句话定位

独立设计并开发本地优先的收藏知识管理工具，将小红书收藏转化为可检索 Markdown 知识库，并通过收件箱状态、失败恢复、质量标记、分层看板和交互式知识画布，完成从原始收藏到本地复用的闭环。

## 用户问题

- 收藏内容停留在平台内部，难以长期控制和复用。
- 收藏数量增长后，关键词、分类和标签无法共同工作。
- AI 整理容易把模型推断伪装成原帖事实。
- 采集、处理和入库失败时，用户缺少恢复路径。

## 产品方案

```text
采集 → Inbox 确认 → AI 整理/降级保存 → Markdown Vault
                                      ↓
                         列表 / 搜索 / 看板 / 画布 / 详情
```

关键决策：先做可验证的本地闭环和知识结构浏览，再根据真实问题集判断是否值得引入向量 RAG，而不是把 RAG 当作产品价值本身。

## 个人贡献

- 负责问题定义、产品边界、交互路径和本地优先架构设计。
- 实现 Express API、收件箱状态流转、Markdown Vault 增量写入和 AI 管线。
- 实现原生 SVG/HTML 交互画布：节点、层级边、拖拽、平移、缩放和过滤。
- 设计失败重试、AI 质量状态和来源数据边界，降低错误内容被误用的风险。
- 编写自动测试、API 冒烟和浏览器回归，维护安全红线与测试数据隔离。

## 固定演示流程

1. 展示 Inbox 中的待处理内容和采集时间。
2. 选择一篇笔记并确认处理。
3. 展示处理进度、成功/失败/跳过状态。
4. 打开生成的 Markdown 笔记，说明原帖与 AI 区块分离。
5. 在知识库列表中按关键词或标签找回内容。
6. 打开看板，解释领域、分类和笔记节点的关系。
7. 打开画布，演示拖拽、缩放、平移和过滤。
8. 点击画布节点进入详情抽屉。
9. 演示一个失败项的原因和“一键重试”。
10. 说明为什么当前暂缓向量 RAG 和 JSON Canvas 导出。

## 简历表述草稿

### 产品/运营方向

独立设计并开发本地优先的收藏知识管理工具，围绕“采集—确认—AI 整理—Markdown 入库—检索复用”设计完整闭环；通过 Inbox 状态机、失败重试、AI 质量标记、分层看板与交互式知识画布，提升内容可控性和结构发现能力。

独立实现 Node.js/Express 本地服务、油猴采集脚本、Markdown Vault 增量写入和原生 SVG 交互画布；建立 100 项自动测试、API 冒烟和浏览器回归，确保真实 Vault 隔离、回环监听、XSS 转义和 AI 外部数据边界。

## 复盘问题

- 用户是否真的会从画布发现列表搜索无法发现的关系？
- AI 整理结果是否比原帖搜索更节省找回时间？
- 失败重试是足够的恢复机制，还是需要更细的阶段重跑？
- 哪些真实问题值得向量检索，关键词检索在哪些场景已经足够？
- 画布在节点数量增长后是否仍然帮助理解，而不是增加视觉噪音？
