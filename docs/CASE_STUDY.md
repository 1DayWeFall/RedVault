# RedVault：用户需求与 Vibe Coding 项目记录

这份文档服务于简历和面试准备，不把 RedVault 包装成大型软件工程项目。它要证明的是：我能从自己的真实使用经历中发现问题，提出产品假设，快速做出可用版本，再根据反馈收缩或调整方向。

## 项目一句话

我把自己长期积累的小红书收藏，做成了一个可以真正使用的本地知识库：收藏先进入收件箱，确认后再整理成 Markdown，并通过列表、搜索、看板和画布帮助自己重新找到和理解内容。

## 我观察到的问题

我原本会收藏很多“以后可能有用”的内容，但收藏之后通常不会再打开。问题并不是没有收藏功能，而是：

- 内容留在平台内部，过一段时间很难重新找到；
- 收藏很多，但缺少适合自己的分类和整理方式；
- AI 可以帮忙总结，但如果没有原文和状态区分，我不敢完全相信整理结果；
- 采集或 AI 处理失败时，系统应该告诉我发生了什么，而不是让内容悄悄消失。

这让我把项目目标从“抓取小红书内容”调整为“让收藏真正变成可以复用的个人知识”。

## 我做出的产品判断

### 先建立可控的主流程

我把主流程收缩为：

```text
收藏 → 收件箱 → 用户确认 → 整理 → 本地笔记 → 找回和复用
```

用户确认被放在 AI 之前，是为了避免一开始就消耗模型额度，也让用户知道哪些内容已经进入自己的知识库。

### 原文和 AI 结果分开

原帖内容保留不动，AI 摘要、分类和标签作为补充信息写入。这样即使 AI 整理错了，用户仍然可以回到原文判断，而不是面对一篇无法追溯的“机器改写”。

### 画布不是为了炫技

列表适合找一篇具体笔记，看板适合理解分类，画布则用来观察“我到底收藏了哪些主题”。我把画布提前加入，是因为它能帮助验证一个重要问题：分类结构是否真的能帮助用户理解自己的知识，而不只是增加一个页面。

### 暂时不急着做 RAG

我先用关键词、标签和分类验证“能不能找回内容”。如果真实使用中确实存在关键词无法解决的问题，再决定是否增加向量检索。这样可以先验证需求，再增加复杂度。

## 我如何使用 Vibe Coding

Vibe Coding 对我来说不是让 AI 替我做产品决策，而是把“想法—尝试—观察—修改”的周期缩短：

1. 先用自然语言描述用户问题和希望验证的行为。
2. 让 AI 快速生成一个可以操作的最小版本。
3. 亲自使用，记录哪里看不懂、哪里不可信、哪里无法恢复。
4. 把问题重新翻译成更具体的产品规则和交互变化。
5. 让 AI 修改代码，再通过实际操作和基础测试确认变化没有破坏主流程。

在这个过程中，我的主要工作不是记住每一行代码，而是判断：这一功能是否服务于用户问题、当前版本是否做得过多、出现失败时用户是否知道下一步该做什么。

## 迭代过程中的取舍

| 观察 | 调整 |
| --- | --- |
| 收藏内容很多，但用户没有确认就直接整理会失控 | 增加 Inbox 和确认步骤 |
| AI 输出不一定可靠 | 保留原文，增加整理状态和来源提示 |
| 只看列表很难理解收藏结构 | 增加看板和交互画布 |
| 一开始想直接做 RAG | 先保留关键词搜索，用真实问题决定是否继续 |
| 失败后只能重新开始 | 增加失败原因和重试入口 |

## 当前可用版本

- 可以从浏览器登录态采集收藏并进入收件箱；
- 用户确认后，内容可以整理为本地 Markdown 笔记；
- 没有 AI 配置时仍然保存原文，不阻断流程；
- 可以通过关键词、分类和标签找回笔记；
- 可以用看板和画布浏览自己的收藏结构；
- 失败项会保留状态，并支持重新进入待处理流程。

## 目前已经确认的事实

这些是项目当前的工程事实，不代表用户价值已经被充分证明：

- 自动测试：100 项通过，向量存储测试暂未启用；
- 看板接口和异常数据处理已覆盖测试；
- 浏览器中已验证画布加载、节点打开详情和关键词过滤；
- Windows 启动入口可以隐藏服务窗口并自动打开页面。

## 下一步要验证什么

下一步不是继续堆功能，而是使用至少 5 篇真实收藏，观察：

- 我是否真的会在几天后回来找这些笔记；
- 分类和画布是否比单纯搜索更容易帮助我发现内容；
- AI 整理是否节省了重新阅读原帖的时间；
- 失败重试是否足够清楚；
- 哪些找回问题是关键词搜索解决不了的。

## 面试表达草稿

### 用户研究/产品方向

我因为长期收藏内容却很少回看，开始拆解“收藏之后为什么无法复用”这个问题。通过 Vibe Coding，我快速做出了一个从采集、确认、整理到找回的最小闭环，并在使用过程中不断调整产品边界：保留原文、增加失败恢复、把看板和画布作为结构发现工具，同时暂缓 RAG，先验证关键词搜索是否已经解决主要问题。这个项目让我练习了从个人行为观察提炼需求、设计验证路径和根据反馈做取舍。

### 更短的简历表述

独立发起并用 Vibe Coding 落地个人收藏知识库项目：从“收藏后无法回看”的真实痛点出发，设计收件箱确认、原文保留、AI 整理状态、失败重试和知识画布，围绕“收藏能否真正被找回和复用”持续验证产品方案。

## 面试时不要主动强调的内容

- 不把项目说成复杂的 AI 基础设施；
- 不把测试数量当作核心成果；
- 不声称已经证明了用户规模化需求；
- 不把 AI 生成的代码表述成完全由自己独立手写；
- 不在没有真实记录时编造节省时间、成功率或用户增长数据。
